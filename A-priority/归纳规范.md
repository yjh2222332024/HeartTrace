# 字幕方法论归纳规范

> 用途：从 B 站直播切片字幕中提炼方法论时，判断**什么能采纳、什么要存档**。
> 适用阶段：跨篇主题归纳（Phase 2+）。

## 一、与 `prop.md` 的分工

| 文档 | 管哪一段 | 处理粒度 |
|---|---|---|
| `prop.md` | 单篇提取：字幕 → 结构化 JSON | 1 篇 → 1 份 JSON |
| **本规范** | 跨篇归纳：原文 → 规则族 | N 篇 → 1 个主题文件 |

`prop.md` 只要求「单案例抽出的规则统称候选规则，等待跨案例验证」。
**本规范就是那个"跨案例验证"的执行标准。**

---

## 二、核心前提：主播说的话 ≠ 方法论

直播切片里，主播的话**至少有六种不是方法论**。直接照搬会把噪声写进 Skill。

### 噪声类型清单

| 类型 | 识别特征 | 实例 |
|---|---|---|
| **N1 反串 / 玩梗** | 极端化表述；语境有逗乐、弹幕起哄；**与主播自己反复强调的原则矛盾** | `BV1qb17BxEQZ:71-82` 投稿者辱骂对方后，主播称「你这么骂他，他对你肯定会心动」 |
| **N2 跑题闲聊** | 由投稿中的某个词触发的即兴联想，与该案例的判断无关 | `BV159BxBdEc8:45-108` 由"发红包"联想到人民币玩家路线 |
| **N3 刻板印象调侃** | 对地域 / 国籍 / 专业 / 性别的整体化调侃 | `BV1DNyVBaEte:344-363`「西安男人不会规划未来」；`BV1z6kzB2EB5:600-607`「学小语种的男生大概率是神」 |
| **N4 建模评价** | 给投稿者外貌打分（夯 / 顶美 / 建模在我之上） | 几乎每篇都有 |
| **N5 弹幕互动** | 回应弹幕、读评论、与观众斗嘴 | 穿插在分析中 |
| **N6 判断失误** | 主播确实给出了有害建议，且不是在玩梗 | `BV1qb17BxEQZ:71-82` 与 B9 冲突 |

### 关于 N2 的重要补充：跑题 ≠ 一定是噪声

跑题段中**可能析出真方法论**。`BV159BxBdEc8:45-108` 的红包话题对该案例是跑题，
但其中「三五千起」「别打整数，打 2480」是有结构的打法内容。

**处理**：跑题段若含可迁移的判断结构，**另立规则并标注来源为"游离内容"**，
但**不计入该案例的因果判断**。

## 三、采纳分级

| 级别 | 标准 | 去向 |
|---|---|---|
| **A 采纳** | 主播自述反复讲过 / 被投稿者引用 / 3 篇以上独立出现 | 规则主体 |
| **B 采纳（标注）** | 2 篇出现，措辞不同但结构相同 | 规则主体，注明"2 篇复现" |
| **C 不采纳** | 仅 1 篇出现，且无自述复现 | 不进规则，留档观察 |
| **D 反例存档** | 与 A 级原则冲突，或触碰边界 / 安全底线 | 写入文件的「已知空缺」，**不进规则** |

**单篇出现的规则一律不采纳**——这正是上一轮 per-case 提取失败的根因：
57 条方法里 inference 一字不差重复 13 次，那是模板复用，不是复现。

---

## 四、最强采纳信号：主播的"自述复现"

以下三种形态是 **A 级**的充分条件，优先级高于出现次数：

1. **主播自述重复过**
   - `BV1DNyVBaEte:369-374`「**我之前我说啥来着**，Nobody knows better than me，
     是不是我说了男生一点害羞就是绝杀啊」→ advancement.md P8
   - `BV1SfBcBLEHs:76-85`「我怎么记得之前有人问我约会去哪好，**我说过要去水族馆**……
     我说过水族馆，陶艺店」→ advancement.md P6

2. **投稿者引用主播的话**（说明已传播，是标志性观点）
   - `BV1SfBcBLEHs:43-45`「时刻提醒着**上头越快，女生下头越快**」
   - `BV1qb17BxEQZ:107-108`「**你上次说的可是让我直接半夜轰炸他呀**」

3. **主播现造但结构完整**（如"俄式打法"）——这类不是稳定规则，
   但反映了**按对象特征生成策略**的思维模式，应作为元规则提取，
   而不是把"俄式打法"本身当成一种固定打法。

---

## 五、用一致性识别反串（核心方法）

> **如果某句话与主播在别处反复强调的原则冲突，优先判定为玩梗 / 反串 / 即兴，
> 而不是方法论。**

主播的内容存在可检验的内部一致性。矛盾处即为噪声，不是"辩证"。

**实例**：`BV1qb17BxEQZ:71-82`
- 主播说：辱骂对方「他对你肯定会心动……你俩的故事就没完了」
- 但主播在别处反复讲：不紧不慢（`BV1SfBcBLEHs:507-515`）、
  明确拒绝后应停止（boundaries.md B9）
- → 判定为玩梗，不采纳

**操作步骤**：提炼一条新规则时，先检查它是否与已确立的 A 级规则冲突。
冲突则进入「已知空缺 · 反例存档」，不进规则主体。

---

## 六、与安全底线冲突时，一律不采纳

不论复现多少次，以下内容**不进规则**：

1. 以承受骚扰 / 伤害作为效果衡量标准
   （`BV1qb17BxEQZ:134-159` 用"能否收到性骚扰私信"判断美式打法是否适合）
2. 鼓励纠缠、监视、报复、情感勒索
3. 以自我伤害胁迫对方
4. 将控制、贬低、越界解释为亲密的表现

这类内容写入「已知空缺」并注明**为什么不采纳**——反例本身有教学价值，
但绝不能进入建议输出。

---

## 七、规则卡的强制字段

参照 `advancement.md` / `boundaries.md` 的既有格式，每条规则必须包含：

```
## <编号> · <规则名>

**判断式**：如果 X，在条件 C 下，更支持 Y 而不是 Z
**机制**：为什么成立（一句话）
**证据**：`BV:行号` 原文引述（至少 1 条，A 级需 2 条以上）
**失效条件 / 例外**：什么情况下不适用
**风险 / 反信号**：误用会怎样
```

**可选字段**：操作（步骤化动作）、另见（交叉引用）、注（条件化说明）。

**硬性要求**
- 证据必须带 `BV:行号`，可回溯原文
- 引述保留 ASR 原样，不润色
- 已确认有害的内容不进"操作"字段

---

## 八、处理流程

1. **选篇**：`python index_cases.py --type <主题> --size`
2. **精读**：读原文，不读上一轮的 per-case JSON（只把 JSON 当索引）
3. **标记噪声**：边读边按 §二 分类，跑题段单独存"游离内容"
4. **提炼规则**：按 §七 写卡
5. **一致性校验**：按 §五 检查是否与已确立的 A 级规则冲突
6. **安全校验**：按 §六 过滤
7. **定级**：按 §三 标 A/B/C/D
8. **回填**：新发现的 A 级信号若属于其他主题，记入该主题的待补清单
