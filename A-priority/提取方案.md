# 恋爱方法论提取方案（提取文档 v1）

> 目标：从 `A-priority/恋爱方法论_JSON_68份`（57 份有效案例级 JSON）提炼出**跨案例验证的恋爱方法论规则库**，最终产出主题 Skill（方案 A：恋爱方法论工具箱）。
> 依据：nuwa-skill 的 [extraction-framework.md](../nuwa-skill/references/extraction-framework.md) 三重验证 + [skill-template.md](../nuwa-skill/references/skill-template.md) 主题 Skill 结构 + prop.md 的单案例提取原则。

---

## 一、输入盘点

| 项 | 数值 | 说明 |
|---|---:|---|
| 输入文件 | 68 份 JSON | 每份 = 一个视频的案例级提取 |
| 有效案例 | 57 份 | 11 份 `has_valid_case: false`（~741B 空壳），剔除 |
| candidate_methods | 57 条 | 每份 1 条，含 if 信号→推断→行动→例外→风险→反信号 |
| recommendations | 57 组 | 每份 1 组建议 |
| danger_flags | 47 条 | 危险信号（越界/纠缠/安全） |
| 证据链 | fact_id / signal_id | 已结构化，可追溯 |

**原料特点**（决定提取策略）：
1. 每案例恰好 1 条 candidate_method → 聚合阶段做**规则聚类**，不靠单文件多规则
2. 证据是 B 站 AI 字幕逐字引文（无标点、无说话人标签）→ 引文只做溯源，不进正文
3. 案例覆盖多个关系阶段 → 天然支持"跨场景复现"验证

---

## 二、核心提取逻辑：规则的三级验证

对 57 条 candidate_methods 聚类后，按以下标准定级（对照 nuwa 三重验证，适配到恋爱领域）：

| 级别 | 标准 | 去向 |
|---|---|---|
| **验证规则** | ≥3 个案例复现同一推断结构（不同投稿者、不同视频） | 规则库主体，进 Skill |
| **候选规则** | 2 个案例复现 | 规则库附"待验证"分区 |
| **案例启发式** | 仅 1 案例支持 | 不进 Skill，仅留档 |

复现判定不要求措辞相同，要求**推断结构相同**：
`输入信号类别（如 rejection_cue）+ 条件（如"明确拒绝且无替代方案"）→ 推断（"视为边界而非考验"）`

**信号类别对齐**：案例 JSON 的 key_signals.category（rejection_cue / interest_cue / mixed_cue / boundary_violation / healthy_cue 等）作为聚类主键之一。

**分域验证**：按关系阶段（追求/暧昧/恋爱/分手后/婚姻前）分域统计复现次数，同一结构跨 ≥2 个阶段复现 → 升级为"较强可迁移"，并记录领域差异作为 exceptions。

**矛盾处理**（nuwa 原则：矛盾是特征不是 Bug）：专家在不同案例中对同类信号给出相反判断时，不强行调和，记录为**条件分歧**——找出区分两种判断的条件差异（如"拒绝后是否给出理由"），这往往是最有价值的规则边界。

## 三、每条规则的输出 schema

```json
{
  "rule_id": "R001",
  "rule_name": "",
  "statement": "如果 X，在条件 C 下，更支持 Y，而不是 Z",
  "signal_categories": ["rejection_cue"],
  "relationship_stages": ["追求期"],
  "then_inference": "",
  "alternative_explanations": [],
  "exceptions": [],
  "counter_signals": [],
  "risks": [],
  "case_count": 3,
  "source_cases": [
    {"bv": "BV...", "video_title": "", "fact_ids": ["F1","F2"], "signal_ids": ["S2"]}
  ],
  "generality": "较强可迁移/可能可迁移",
  "confidence": "high/medium/low",
  "tension_with": ["R012"]
}
```

规则间张力（tension_with）显式记录，供 Skill 使用时呈现"取决于条件"而非伪一致。

## 四、执行流程

### Phase 1 · 清点校验（脚本自动）
- 剔除 11 份无效文件，生成 `有效57份清单.json`（含 BV、标题、时长、方法名、信号类别集）
- 校验 JSON 合法性、fact/signal 引用完整性

### Phase 2 · 分批精读（4 并行子代理）
- 57 份按字节均衡分 4 批（每批 ~14-15 份）
- 每个子代理对每份案例输出**标准化规则卡**（按第三节 schema），并把该案例的 danger_flags、recommendations 一并归一化
- 产出：4 份 `规则卡_批N.json`

### Phase 3 · 跨案例验证聚合（主对话）
- 合并 4 批规则卡，按"信号类别 + 推断结构"聚类
- 统计复现次数 → 三级定级（验证规则/候选规则/案例启发式）
- 分域统计、识别条件分歧与张力对
- 产出：`恋爱方法论_规则库.json`（预计 15-25 条验证规则 + 候选区）

### Phase 4 · 主题 Skill 生成
按 nuwa skill-template 的主题 Skill 变体产出 `恋爱方法论/SKILL.md`：
- **触发**：用户描述情感困扰、关系判断、信号解读时激活
- **结构**：核心规则库（按关系阶段分组）→ 决策启发式 → 信号词典（category → 解读 → 强度）→ 危险信号清单（不可自动化，直接提醒现实支持）→ 诚实边界（单方叙述/AI 字幕/非专业咨询）
- **表达**：中性专业（主题 Skill 不模拟主播语气），规则陈述用"如果…在…条件下…更支持…"
- 生成后按 extraction-framework.md 第六节清单自检

## 五、安全与诚实边界（写入 Skill 本体）

1. 所有规则来自**投稿者单方叙述**，Skill 使用时须提示"基于单方信息，建议核实在做判断"
2. danger_flags 涉及越界/纠缠/人身安全的内容**只提醒寻求现实支持**，不生成"如何追回"建议
3. AI 字幕的转写噪声（人名代词错乱，如"小静/小宁"混用）→ 规则不依赖具体人名细节
4. 声明：非专业心理咨询，严重情况（自伤/家暴/跟踪）转介专业资源
